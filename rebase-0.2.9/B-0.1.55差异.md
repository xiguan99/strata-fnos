# B. 引擎 0.1.52 → 0.1.55 指令/默认值差异实证

来源只用三种：上游 release notes（`release-v0.2.8.md` / `release-v0.2.9.md`）、`docs/DETAILS.md`（0.2.7 vs 0.2.9 两份逐段比对）、两台引擎实拉 `--help`。不写推断。

## 一、硬结论：`--help` 逐字零差异

```
cd xe55 && LD_LIBRARY_PATH=. ./strata serve --help > new-serve.txt   # 273 行
cd 0.1.52 bundle && LD_LIBRARY_PATH=. ./strata serve --help > old-serve.txt
diff -u old-serve.txt new-serve.txt   → 无输出（同样对 strata --help 做过，272 行，也无输出）
```

即：**没有 flag 新增、删除、改名，也没有默认值变化**（`--help` 文本里带默认值，如 `--spec`、`--kv`、`--pipeline-windows`、`--prefill`、`--host-core`、`--ple-*` 全部原样）。二进制本身变了（`strata` sha256 `a56675fa…` → `27875ca8…`，`libstrata_kq.so` 也变；`libcudart/libcublas*` 三个 CUDA 库**逐字节相同**），`BUILD.json` archs 仍是 `60,61,70,75,80,86,89 / ptx true / cuda 12.9`。

## 二、你的三个问题

### ① `STRATA_SM75_PERF` 还在不在、还必不必要

- **在**：0.1.55 二进制里仍有该变量（strings 命中 1 次）。
- **文档逐字未变**：0.2.9 `DETAILS.md:1069` 与 0.2.7 `DETAILS.md:1050` 同一段原文——「Nobody on the team has an sm_75 card to confirm them, so they are off until asked for. `STRATA_SM75_PERF=1` turns on every bitwise Turing kernel on a 7.5 card」，同段还有 `STRATA_SM75_IL`、`STRATA_SM75_EXP`、`STRATA_GR_UP75`、`STRATA_GR_DOWN_TG`、`STRATA_SCORES_HALVE`、`STRATA_TC_SM75`、`STRATA_PA_V1_PREFETCH`、`STRATA_SCORES_THREAD` 等单项开关。
- **结论：仍默认关闭、仍然必要**（要用就得设 1）。是否还有 +22% 的收益，靠实测开关各 3 次说话。

### ② `--spec / --kv / --pipeline-windows / --host-core / --prefill / --ple-*` 有无改名或语义变化

**无改名、无语义文本变化**（见第一节 diff 为空）。附 0.1.55 实拉原文几行备查：

```
--kv fp16|int8 | q4_0 | k8v4        KV storage …(min 20480 for --kv-resident)
--kv-resident N                     keep N cells of each QSA layer in VRAM (min 20480)
--pipeline-windows N                --serve with a layer split on two GPUs (on by default for 2+ stages on AMD gfx12)
--host-core auto|first|last         processor core for the engine thread
--prefill auto[:N]|N                prompt reading
--ple-gguf / --ple-io / --ple-row-cache / --ple-inflight / --ple-delay-us / --ple-sync-submit
--spec N / --spec-min-p P           MTP drafter verify window / extension confidence
```

### ③ `--batch ≥2` 时自动设的「九项」是哪九项、会不会覆盖我们 preset

上游原文（`release-v0.2.9.md:9`）：「With `--parallel` or `--batch` of 2 or more, the server now sets the nine qualified settings itself.」、`:27`「Any environment variable or config value you set still wins.」

源码原文（`control-0.1.55/serve/server.py:3676`）：

```python
PARALLEL_STACK_ENV = {
    "STRATA_CKPT_POOL": "1", "STRATA_CKPT_POOL_READY": "4", "STRATA_SLOT_CKPT_MOVE": "1", "STRATA_SLOT_COPY_DIRECT": "1",
    "STRATA_SLOT_COPY_BATCHSYNC": "1", "STRATA_BATCH_GDN_GROUPS": "1", "STRATA_BATCH_ATTN_ROWS": "1",
    "STRATA_BATCH_SELF_COMMIT": "1", "STRATA_QSA_SLOTS": "1",
}
```

触发条件（`parallel_stack_env()` 全文）：`parallel_slots(cfg) >= 2`（取 args 里的 `--batch`/`--slots`，否则 `parallel`>1）、非 `deepseek41`、非 sycl/metal/vulkan、Linux、非 hip。

**会不会覆盖我们的 preset：不会。** `child_env()` 的执行顺序是「`os.environ` → `CUDA_VISIBLE_DEVICES` → `cfg["env"]`（预设/env 面板，硬覆盖）→ `deepseek_slot_env` → `parallel_stack_env` → `gdn_stack_env`」，后两个全部用 `env.setdefault`，注释原话「An explicit environment variable (or the config's "env") still wins: =0 turns one off.」预设写同名变量即赢，写 `=0` 即关闭。

**但要注意一个行为差**：我们跑 `--batch 2` → 0.1.55 会**自动多出这 9 个变量**（0.1.52 没有）。所以「0.1.52 vs 0.1.55 同一份预设」并不是同一套 env；实测会同时含引擎改进 + 这 9 项。若要把两者拆开，只需在预设 env 里把这 9 项写 `0` 再跑一轮。

## 三、新增 env 18 个（二进制 `STRATA_*` 名集合差：+18 / −0）

| 变量 | 上游文档说明 | 说明 |
|---|---|---|
| `STRATA_ARENA_RAM_WAIT_S` | DETAILS:713 | arena 装不进空闲 RAM 时的等待秒数（新默认 **20 s**，`0`=立刻加载）。配套：服务器结束「上一轮遗留引擎」的等待从 10 s 提到 **120 s**（#4051）——这条与我们的 ready 真实性强相关 |
| `STRATA_SPEC_COST` | DETAILS:569 | 旧的 `--spec` 成本规则；不设时引擎提示一次并沿用新规则 |
| 其余 16 个 | 无（release notes 与 DETAILS 均无记载） | `STRATA_BATCH_CONCURRENT_READ`、`STRATA_CRASH_BT`、`STRATA_GDN_TC_FUSE`、`STRATA_GDN_TC_NP`、`STRATA_GDN_TC_TILES`、`STRATA_GR_R2`、`STRATA_HH`、`STRATA_P4_TIMING`、`STRATA_P4_TRACE`、`STRATA_PAR_COUNTERS`、`STRATA_PF_TILE_DEBUG`、`STRATA_PF_W16_CACHE_MIB`、`STRATA_PH`、`STRATA_PIPED_CONCURRENT_MIN`、`STRATA_PREFILL_LM_FORCE`、`STRATA_SM121_PERF` |

这 16 个是引擎内部/调试开关，**名字可核、用途上游未公开，我不猜**；不在我们的预设里，不设即走引擎默认分支。

被移除的 env：**0 个**（`comm -23` 只命中一段被拉长的拼接串，非真实变量）。

## 四、对我们配置有实际影响的默认变化（0.2.9 文档原文）

1. **并行栈自动开**（见 ③）：`--batch 2` → 多 9 个 env。文档给的效果是 c=8 并发 +16%、单请求「no solo cost」。
2. **GDN 张量核栈**：`STRATA_GDN_TC=1` + `STRATA_GDN_CONVL2=2`，但源码门槛是 `cfg.arch == "qwen4exp"` 且引擎运行时还要求 compute capability ≥ 8 —— 我们是 **sm_75（7.5）**，引擎会自动回退旧内核，**对我们无影响**。
3. **遗留引擎清理**：服务器启动前结束上一轮遗留引擎，等待 10 s → **120 s**（#4051）。这与「谎报 ready」属同一类问题，0.1.55 上游自己补了一半。
4. **arena RAM 检查**：装不下时不再直接拒，改为等最多 20 s 再带警告继续。

## 五、为什么还得是我们自己的 host 补丁

- `request_timings()` 在 0.1.55 里**依然不拼** `hit_rate` / `pcie_share`（`--help` 与 release notes 均无相关条目），所以命中率列这事跟版本无关——而它已按用户口径**取消**。
- 网页「选角色不生效」上游 0.2.9 仍未修（前端仍把推荐卡列表发上去，服务端无「从已存设置取角色」回退）。
- `/health` 在引擎未起时仍返 200 `{"loaded":false}`，ready 判据仍得由 host 侧四项证据兜住。
