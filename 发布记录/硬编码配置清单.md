# strata fnOS 包：硬编码配置清单（2026-10-29 扫描）

口径来自用户：「一切尽量以网页配置为主，我们尽量不硬编码任何配置项，别人用的环境和我们不一样。」
扫描范围只含我们自己的代码：`fnpack/cmd`、`scripts`、`fnpack/app/host/server`、`fnpack/app/control/serve`、`fnpack/app/control/tools`；
`fnpack/app/ui`、`control/python`、`node_modules`、`dist` 等打包产物与第三方运行时不在内。

结论先说：**没有写死本机路径、没有写死显卡序号/卡名**（唯一命中的 `/vol1/1000`、`40HX` 都在注释里）。
写死的是一批「数值经验值」，按可搬性分三档。

## B. 已有网页设置，仅默认值在代码里（可接受，但要知道在哪改）

- 引擎内部端口：`catalog.mjs:102` 的 `server.port`（专家页可改，默认 8080）；`engine.mjs:82`、`models.mjs:213`、`supervisor.mjs:27` 等都读该设置，**没有各自写死**。
- 显存预留：`native-settings.mjs:22` 的 `vram_reserve_mib`（网页可改），缺省 1024。
- 上下文长度：界面可选，`catalog.mjs:118 CONTEXT_TOKENS.recommended = 131072` 只是推荐值，各 family 的 `contextMax`（262144 / 131072）来自模型目录数据。
- 图像 token 上下限：`native-settings.mjs:23-24` 已在设置页。
- 空闲卸载、并行档、MTP 等：`native-settings.mjs` 已在设置页。

## C. 已被这次补丁去掉的写死（记录，防回归）

- 主卡选择：以前 `buildConfig()` 只要文件里有 `"gpu": N` 就直接用裸编号 → 无角色信息时落到 0 号卡（本机是 40HX）。现改为：角色表 → 物理集合 → 引擎侧紧凑编号；角色表缺失时按「上次运行的主卡 / 调优文件」接续，接不上且多卡则**明确报错拒绝启动**，绝不静默用 CUDA0。单卡机器、主卡是 0 号卡、双卡都成立（离线用例 `scripts/test-gpu-roles.py`）。
- 引擎二进制路径：`engine-bundle/<版本>-<平台>-cuda-cuda12` 由安装器组件引用解析（0.2.7.4 修过一次「装完报缺引擎」），不写死绝对路径。

## D. 包外依赖（不是代码，但影响「换台机器能不能用」）

1. **目录授权**：飞牛只允许应用写「应用设置 → 访问权限 → 允许访问以下文件夹」里授权的目录。模型目录要用户自己加（或用命令加：`trim-cli app openapi add-user-auth-path`），应用无法自助申请。包内 `fnpack/cmd/main:prepare_data_dirs()` 会自动建 `models/ packs/ mtp/` 并改属主，但没授权时只能记一条明确日志。→ 建议在开机/加载失败时把这句文案提到界面，而不是只写 info.log。
2. **CUDA 版本**：`engine-bundle` 目录名带 `cuda12`，跟随上游引擎发布；换驱动/别的卡型号时靠引擎自身探测，不写死 sm 架构。
