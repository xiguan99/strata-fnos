## 为什么改

用户口径：「一切尽量以网页配置为主，我们尽量不硬编码任何配置项，别人用的环境和我们不一样。」
Rain 具体要求（m01184）：把 `layer_split`、`kv-resident`、`vram-reserve-mib`、`prefill`、`pool-workers` 与
`STRATA_*` 环境变量做成设置页可编辑项，先做参数透传与默认值。

## 做了什么

### 1) 引擎参数可在设置页编辑（新增 6 项）

| 设置项 | 对应引擎参数 | 说明 |
|---|---|---|
| `kv_resident` | `--kv-resident` | 每层钉在显存里的 KV cells；引擎下限 20480，填更小会被夹到 20480 |
| `vram_reserve_later_mib` | `--vram-reserve-later-mib` | 读完 prompt 后交还给专家缓存的显存 |
| `prefill` | `--prefill` | `auto` / `auto:<tokens>` / 具体块大小 |
| `pool_workers` | `--pool-workers` | 处理器工作线程数 |
| `host_core` | `--host-core` | `auto` / `first` / `last`，引擎线程绑哪个核 |
| `spec` | `--spec` | 提示词查找窗口数，0 关闭 |

已存在的 `layer_split`、`parallel`、`vram_reserve_mib`、`mtp`、`batchMtp`、`drafting`、`ds_experts` 不动。

### 2) 参数透传：设置值就是启动值

保存设置时，除写进该模型的设置项外，同时写进该模型的引擎参数（`args` 与 `user_args`），
下次启动以此为准，不再需要手改配置文件。读取设置时若设置项为空，则回填引擎参数里的实际值，
所以界面上看到的就是引擎正在用的。

### 3) 显存预检的三个数字也进设置页

原来是写死的 `Math.max(2560, reserve+1536)` 与 `needed+512`，现在：

| 设置项 | 默认 | 作用 |
|---|---|---|
| `vram_floor_mib` | 2560 | 该模型在这张卡上首次加载所需的最小空闲显存 |
| `vram_extra_mib` | 1536 | 在「给别的应用留的显存」之上再加多少，二者取大作为首载地板 |
| `vram_headroom_mib` | 512 | 上次实测需要量之上的余量 |

**默认值与改动前完全一致**，预检严格度没有放宽（Rain 明确要求不放宽）。

## 实测（0.2.7.10 装机态）

- 设置页 `PATCH /api/native/models/swift-iq3_s/settings` 写入 `kv_resident=20480`、
  `host_core=last`、`prefill=auto:32768`、`vram_reserve_later_mib=1700` 后，
  该模型运行配置的 `args` 与 `user_args` 同时出现这四个参数（实测回读一致）。
- 加载后引擎日志确认参数生效：`29 pool workers ... the host thread on 35 (draining too) (--host-core last)`，
  引擎 `session is up (engine 0.1.52)`。
- 性能与改动前同档（双卡 main=1/helper=2，80K probe）：
  8K 预填充 **980.4** T/S、解码 **77.3** T/S；80K 预填充 **1663.2** T/S、解码 **90.0** T/S。
- 显存预检用默认值仍能正常起（两卡 20702 / 21262 MiB），没有把装得下的加载判死。
