# strata v0.2.7.7（2026-10-30）

## 改（去硬编码，第一项）
- 对外端口不再写死 `8791`，改为**以本包 manifest 的 `service_port` 为准**，拿不到合法值（缺文件 / 非数字 / 越界）才退回 `8791`：
  - `fnpack/cmd/main`：新增 `manifest_port()`，`export STRATA_PORT="${STRATA_PORT:-$(manifest_port)}"`；环境变量仍可覆盖（排障用）。
  - `fnpack/app/host/server/index.mjs`：`PORT = Number(process.env.STRATA_PORT ?? manifestPort() ?? 8791)`，`manifestPort()` 读 `resolve(ROOT,'..','manifest')` 的 `service_port`。
  - 效果：别人换端口只改 manifest 一处，桌面图标端口、后端监听端口同时跟着走，不用改代码；两处源码不再各存一个 8791。
- 本包 `service_port` 仍是 `8791`，装机后行为与 0.2.7.6 一致（桌面图标 / 浏览器访问端口不变）。

## 加（仓库纪律）
- `.gitignore`：新增 `*.fpk` 与引擎二进制忽略规则（`fnpack/app/engine-bundle/*` + 反选保留 `BUILD.json`/`SYSTEM-LIBS.txt`/`engine-component.json` 等元数据）。写法要点写进注释：必须忽略目录内容而不是目录本身，否则 `!` 反选对子目录无效。
- `README.md`「构建」段：写明引擎二进制永久不入 git 及原因（单文件几百 MB，`git add -A` 会暂存 684MB → push 408、仓库撑到 GB 级），只随 fpk 与 Release 资产发布。

## 自测
- 端口解析单测（bash `manifest_port()` 与 node `manifestPort()` 两侧同口径）：`TRIM_SERVICE_PORT=8792` → 8792；无该变量、manifest 写 8795 → 8795；非数字/越界 → 8791；缺文件 → 8791；`STRATA_PORT` 环境变量优先级最高。
- 装机实测（0.2.7.7 装好后）：默认 manifest `service_port = 8791` → `curl 8791/api/hardware` **200**，`info.log` 记 `启动 strata host (端口=8791, …)`；把装机目录 `/var/apps/strata/manifest` 改成 `8792` 重启 → `curl 8792/api/hardware` **200**、8791 拒连、日志记 `端口=8792`；改回 8791 重启 → 8791 恢复 200。**桌面图标端口与后端监听同源，改 manifest 一处即同走。**
- 顺带查明 fnOS 布局（这条写进代码注释，免得后人再踩）：`TRIM_APPDEST` 指向 payload `/vol1/@appcenter/strata`，**manifest 不在 payload 里**，而在 `/var/apps/<app>/manifest`；fnOS 启动时还会把它读成 `TRIM_SERVICE_PORT` 注入环境。所以取值顺序是 `TRIM_SERVICE_PORT` → `/var/apps/<app>/manifest` → `payload/manifest` → 8791。
- 验收仍按 `发布记录/验收流程.md`：真实入口加载 + 发请求看 T/S，本次未动引擎参数，模型加载/测速结果见下方回执。

## 预填充调参复测（Rain 交办：`--vram-reserve-mib` 1024 / 1536 × 输入约 0.5K / 2.2K）

同一条提示词、同一张卡（RTX 2080 Ti 22GB，`CUDA_VISIBLE_DEVICES=1`）、`--kv-resident 16384`、`--max-context 262144`、2 并发、每次都是新实例首次请求（`cached_tokens=0`，不吃会话缓存）：

| `--vram-reserve-mib` | 555 token 预填充 | 2245 token 预填充 |
|---|---|---|
| 1024 | 169.6 tok/s | **533.4 tok/s** |
| 1536 | 171.0 tok/s | 493.7 tok/s |

- 短输入两档持平（差 0.8%，噪声内）；长输入 1024 快约 8%。**保留 `--vram-reserve-mib 1024`**（`native-tune/swift-iq3_s.json` 与实例 args 一致）。
- 800 tok/s 的预填充基线**仍未达标**：2.2K 输入最好 533 tok/s。数据比上一轮（`reserve 512`、459 token 冷态 160.9 tok/s）好看，但差距仍在，如实记录，不当达标。
- 生成侧同批测得 43.8–70.2 tok/s（热态多次 45–55），50 tok/s 基线在热态可达。
- 复测完已 unload，两卡回到空闲（各 1 MiB）。

### 复测期间遇到的两件环境事实（不是套件问题，记下来免得下次误判）
- **40HX 掉了**：`dmesg` 显示 `NVRM: GPU 0000:03:00.0: RmInitAdapter failed! (0x62:0x40:2119)`、`kgspBootstrap_TU102: CMP40_COMPUTE_UNLOCK_V274: POST_FWSEC_COMMIT_FAIL`、`Max GSP-RM boot attempts exceeded: 4/4`，驱动随后整体 unload。当前 `nvidia-smi -L` 只剩两张 RTX 2080 Ti（bus 83:00.0 / 84:00.0，各 22528 MiB），40HX 不在列。**视频平台依赖 GPU0（40HX），在那张卡回来之前它跑不了。**
- 驱动整体 unload 时 strata host 进程被一起带走（无优雅停止日志，应用中心仍显示 `start`），**不是套件崩溃**：`trim-cli app restart strata --yes` 后立即恢复（`/api/hardware` 200）。卡重新枚举后角色表 `{"0":"off","1":"main"}` 仍按物理 index 生效，日志三行照打。
